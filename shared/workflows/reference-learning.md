# 参考学习与探索

分析请求只分析；“吸收”“提炼下来”“沉淀”或明确要求更新 Skill 时，才写回相关知识。一般生成不自动修改仓库，提交和发布按当轮指令处理。

## 提炼

从参考图、实际结果或反馈中抽出还能用的规则：作用、条件、调整方法和判断标准。

- 哪些可见关系支撑了效果，哪些只是该图的表面元素？
- 换人物、场景、尺度或媒介后，哪些关系仍有用，哪些需要调整？

不能确认因果时不要写成规则。完整画面的关系同时考虑景别、动作、空间和光色；局部学习只提取所需部分。不把一次成图写成稳定规律。

## 探索与验证

按请求交付候选方案、提示词、比较或实际图片。探索方向应在视觉关系上有有效差异；修复主要缺陷时集中调整相关因素，研究单一因素时尽量固定其他条件。执行次数、时间和成本服从本轮限制；采用有限批次，无改善时更换方法或停止并报告。

在当次回复里说明方案是否实现。用户否定的当前结果不写入正向规则；原因不明时不将颜色、衣饰或风格整体拉入禁用清单。需要验证迁移时选不同人物、场景或媒介，不只重复原构图。

## 无参考图探索

无参考图的人物与妆造探索由人像创作入口处理，仅用文生图：可观察历史作品学习，但输入只含文字，不传身份图、历史成片或本轮候选，也不通过编辑模式追加后期。每轮新建成年人物，不承诺同一身份。给原图化妆由参考图化妆入口处理，必须使用原图编辑；不能以本节的文字探索替代。明确的身份参考和风格参考按其指定角色使用。

## 写回

|内容|位置|
|---|---|
|专业方法与适配条件|对应 Skill 的 `references/`|
|跨专业关系与判断方法|`shared/methods/`|
|学习和更新操作|`shared/workflows/`|
|可复用的画面关系|`shared/cases/`；更新[案例索引](../cases/index.md)|
|纳入案例的图片|`shared/assets/`，通过相对链接引用|

优先修正或合并现有方法，只有具体复现需要才新增案例。一个规则只保留一个维护位置，其他文件按需引用；案例不复制任务权限、身份和交付规则。

Skill 文件是给别人下载使用的生产资料。只写当前要执行的规则、条件和操作。不写会话过程、日期、用户原话、验收经过、样本成败或规则为何改成这样。交接笔记、评审记录和生成结果目录不提交。

保留已有未提交改动；未经授权不将私人原图写入公开仓库。修改后检查相关引用、适用范围和相互冲突的规则；保存文字不等于完成效果验证。
