# 参考学习与探索

分析请求只分析；“吸收”“提炼下来”“沉淀”或明确要求更新 Skill 时，才写回相关知识。一般生成不自动修改仓库，提交和发布按当轮指令处理。

## 提炼

从参考图、实际结果或反馈中选择与目标相关的证据，记录作用、条件、调整方法和判断依据：

- 哪些可见关系支撑了效果，哪些只是该图的表面元素？
- 换人物、场景、尺度或媒介后，哪些关系仍有用，哪些需要调整？
- 判断来自画面观察、设计推断、生成对照还是用户认可？哪些尚未验证？

不能确认因果时保留为假设。完整画面的关系同时考虑景别、动作、空间和光色；局部学习只提取所需部分。保留来源与证据状态，不把一次随机成图写成稳定规律。

## 探索与验证

按请求交付候选方案、提示词、比较或实际图片。探索方向应在视觉关系上有有效差异；修复主要缺陷时集中调整相关因素，研究单一因素时尽量固定其他条件。执行次数、时间和成本服从本轮限制；采用有限批次，无改善时更换方法或停止并报告。

实际出图后分别记录方案是否实现、助手判断和用户反馈。用户否定的当前结果不作为正向配方；原因不明时不将颜色、衣饰或风格整体拉入禁用清单。需要验证迁移时选不同人物、场景或媒介，不只重复原构图。

## 无参考图探索

妆容的无参考图自进化仅用文生图：可观察历史作品学习，但输入只含文字，不传身份图、历史成片或本轮候选，也不通过编辑模式追加后期。每轮新建成年人物，不承诺同一身份。明确有身份参考、风格参考或原图修改的普通任务按请求执行，不受此专属条件覆盖。

## 写回

|内容|位置|
|---|---|
|专业方法与适配条件|对应 Skill 的 `references/`|
|跨专业关系与判断方法|`shared/methods/`|
|学习和更新操作|`shared/workflows/`|
|具体作品、来源和验证状态|`shared/cases/`；更新[案例索引](../cases/index.md)|
|纳入案例的图片|`shared/assets/`，通过相对链接引用|

优先修正或合并现有方法，只有具体复现需要才新增案例。一个规则只保留一个维护位置，其他文件按需引用；案例不复制任务权限、身份和交付规则。写入适用条件、判断依据与必要操作，不写对话复述、能力宣言或改造理由。

保留已有未提交改动；未经授权不将私人原图写入公开仓库。修改后检查相关引用、适用范围和相互冲突的规则；保存文字不等于完成效果验证。
